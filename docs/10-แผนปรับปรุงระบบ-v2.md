# CWK DutyFlow — แผนปรับปรุงระบบ v2

**โรงเรียนจุนวิทยาคม อำเภอจุน จังหวัดพะเยา**
เอกสารฉบับนี้แปลงความต้องการล่าสุดของผู้ใช้เป็นแผนแก้ไขโค้ดที่ตรวจรับได้
สถานะ: **รอตรวจทานการออกแบบ** → จากนั้นลงมือแก้โค้ด

> หมายเหตุ: รายการที่ทำเครื่องหมาย 🔎 ต้องยืนยันกับซอร์สโค้ดจริงอีกครั้งก่อนแก้ (ชื่อคอลัมน์/ชื่อฟังก์ชันอาจต่างเล็กน้อย)

## 1. ความต้องการ 8 ข้อ → สถานะปัจจุบัน

| # | ความต้องการ | สถานะ | สิ่งที่ต้องทำ |
|---|---|---|---|

| 2 | **อยู่เวรหรือไม่** | ✅ มีแล้ว (`DUTY_LOGS` + สถานะเช็คอิน 6 แบบ) | แปลงเป็นป้ายสถานะ 4 แบบที่อ่านง่าย |

| 5 | หมุนเวร **ข้ามวัน** จ→อ→พ→พฤ→ศ→จ ต่อภาคเรียน | ✅ มีแล้ว (`rotateWeekday`) | ไม่ต้องแก้ — เพิ่มหน้าพรีวิวให้เข้าใจง่ายขึ้น |
| 6 | **หมุนจุดภายในเวรแต่ละวัน** (ใหม่) | ❌ ยังไม่มีแบบรายวัน | **งานใหม่ A** |

| 8 | **รายงานปฏิบัติงานเวรรายวัน** + **สรุปอยู่/ไม่อยู่ แยกกลุ่ม** | ⚠️ มีรายงานรายวันแบบพื้นฐาน | **งานใหม่ C และ D** |

## 2. งานใหม่ A — หมุนจุดภายในเวรแต่ละวัน

### หลักการ
คำนวณ **ตอนสร้างตารางรายวัน** ด้วยสูตร ไม่เก็บตารางซ้ำซ้อน → เร็ว ย้อนกลับได้ ไม่บวมชีต

```
newSeatIndex = (oldSeatIndex + offset) % groupSize
```

หมุนเฉพาะที่นั่งที่อยู่ใน `rotation_group` เดียวกัน วันเดียวกัน ช่วงเวลาเดียวกัน
เรียงตาม `rotation_order` — ที่นั่งที่ **ปักหมุด** จะถูกดึงออกก่อนหมุน แล้วใส่กลับตำแหน่งเดิม

### โหมดที่รองรับ (ตั้งค่าฝั่งแอดมิน)

| `point_rotation_mode` | offset | ใช้เมื่อ |
|---|---|---|
| `OFF` | 0 | ไม่หมุนจุด (ค่าเริ่มต้นเดิม) |
| `SEMESTER` | 0 (ใช้ `ROTATION_apply` เดิม) | หมุนครั้งเดียวต้นภาคเรียน |
| `WEEKLY` | สัปดาห์ที่ของภาคเรียน | หมุนจุดทุกสัปดาห์ ← **แนะนำ** |
| `EVERY_N_DAYS` | `floor(dutyDayIndex / N)` | หมุนทุก N วันทำการ |
| `DAILY` | `dutyDayIndex` | หมุนทุกวัน |

`dutyDayIndex` = ลำดับ**วันทำการที่มีเวร** นับจากวันเปิดภาคเรียน (ข้ามวันหยุด/วันปิดเรียน) 🔎
สำคัญ: นับแบบนี้เพื่อให้วันหยุดไม่ทำให้รอบหมุนเคลื่อน

### ไฟล์ที่เพิ่ม/แก้
- **ใหม่** `src/PointRotationService.gs`
  - `PR_mode_()` , `PR_offsetFor_(date, semesterId)` , `PR_dutyDayIndex_(date, semesterId)`
  - `PR_applyToSeats_(seats, offset)` — หัวใจ ทดสอบแยกได้
  - `PR_preview(ctx, date)` — แสดงก่อน/หลัง ให้หัวหน้าเวรเห็น
- **แก้** `src/ScheduleService.gs` — เรียก `PR_applyToSeats_` ตอน generate
- **แก้** `src/RotationService.gs` — แยกให้ชัดว่า "หมุนวัน" กับ "หมุนจุด" เป็นสองแกน

### กฎที่ต้องไม่ละเมิด
- ไม่แตะ `original_teacher_id` เด็ดขาด — การหมุนจุดเขียน `effective_teacher_id` เท่านั้น เมื่อสร้างตารางใหม่ให้ตั้งค่าทั้งสองครั้งแรกเท่านั้น
- ถ้าวันนั้นมีการเช็คอินแล้ว (`DUTY_LOGS` มีข้อมูล) → **ห้ามหมุนย้อนหลัง** ต้องขึ้นคำเตือนและบล็อก

## 3. งานใหม่ B — กำหนดจุดเฉพาะบุคคล (ปักหมุด)

### แนวคิด
ครูบางคนต้องอยู่จุดเดิมเสมอ (เช่น ครูเวรหน้าประตู ครูที่มีข้อจำกัดทางร่างกาย ครูที่ดูแลจุดเฉพาะทาง)
→ ปักหมุด **ระดับที่นั่ง (seat)** ไม่ใช่ระดับครู เพื่อให้ยังหมุนวันได้ถ้าต้องการ

### คอลัมน์ที่เพิ่มใน `DUTY_ASSIGNMENTS` 🔎

| คอลัมน์ | ชนิด | ความหมาย |
|---|---|---|
| `pin_mode` | `NONE` \| `POINT` \| `SLOT` \| `DAY` \| `ALL` | ระดับการตรึง |
| `pin_reason` | text | เหตุผล (บังคับกรอกเมื่อปักหมุด) |
| `pin_by` | uuid | ผู้สั่งปักหมุด |
| `pin_at` | datetime | เวลาที่ปักหมุด |

ความหมายแต่ละโหมด
- `POINT` — ตรึงจุด แต่ยังหมุนวันได้
- `DAY` — ตรึงวัน แต่ยังหมุนจุดได้
- `ALL` — ตรึงทั้งวันและจุด (เท่ากับ `LOCKED` เดิม)
- `NONE` — หมุนได้อิสระ

ทำงานร่วมกับ `rotation_scope` เดิม (BOTH/DAY_ONLY/POINT_ONLY/NONE/LOCKED) — ให้ `pin_mode` มีลำดับสูงกว่า

### หน้าจอใหม่
**"ตั้งค่าการหมุนเวรและปักหมุด"** (เฉพาะ `DUTY_ADMIN` / `SYS_ADMIN`)
- เลือกโหมดหมุนจุด + จำนวนวัน N
- สวิตช์ "เคารพการปักหมุด" (`point_rotation_respect_pin`)
- ตารางที่นั่งทั้งหมด พร้อมปุ่มปักหมุด/ปลดหมุด + ช่องเหตุผล
- ปุ่ม **พรีวิว 4 สัปดาห์ข้างหน้า** ก่อนบันทึก

สิทธิ์: `DAILY_HEAD` **ดูได้ ปักหมุดไม่ได้** (ปรับเวรรายวันได้ตามที่ให้สิทธิ์ไว้แล้ว)

## 4. งานใหม่ C — รายงานการปฏิบัติงานเวรประจำวัน

`REPORT_dailyPerformance(ctx, date, opts)` → 1 แถวต่อ 1 ที่นั่ง

| กลุ่มคอลัมน์ | รายละเอียด |
|---|---|
| ใคร/ที่ไหน | จุดเวร, จุดย่อย, ช่วงเวลา, ครูตามตาราง, ครูที่ปฏิบัติจริง |
| อยู่หรือไม่ | ป้ายสถานะ: **อยู่ครบ** / **สาย** / **อยู่ไม่ครบ** / **ไม่อยู่** |
| หลักฐาน | เวลาเข้า–ออก, ระยะห่าง GPS (ม.), จำนวนภาพ, ลิงก์ภาพ, เหตุการณ์ที่บันทึก |
| ระดับหลักฐาน | 🟢 ครบ / 🟡 ไม่ครบ / 🔴 ไม่มี |
| การเปลี่ยนเวร | ประเภท, เหตุผล, ผู้อนุมัติ, **ระดับผู้อนุมัติ**, เวลาอนุมัติ |

### เกณฑ์ตัดสิน (ตั้งค่าได้)
```
หลักฐานครบ  = มีเช็คอิน AND อยู่ในรัศมี AND จำนวนภาพ ≥ evidence_min_photos
สาย         = เวลาเช็คอิน > เวลาเริ่ม + late_grace_minutes
อยู่ไม่ครบ    = มีเช็คอิน แต่ไม่มีเช็คเอาต์ หรือ อยู่นอกรัศมี
ไม่อยู่       = ไม่มี DUTY_LOGS เลย และไม่มีการมอบหมายแทนที่อนุมัติแล้ว
```

ส่งออก: หน้าจอ / PDF (Google Docs + ฟอนต์สารบรรณ) / Google Sheets
ปุ่มเดียวบนหน้า "วันนี้" — ไม่ต้องเข้าเมนูรายงาน

## 5. งานใหม่ D — สรุปครูอยู่/ไม่อยู่ แยกกลุ่ม

`REPORT_attendanceByGroup(ctx, from, to, groupBy)`

| `groupBy` | จัดกลุ่มตาม |
|---|---|
| `DEPARTMENT` | **กลุ่มสาระการเรียนรู้** ← ค่าเริ่มต้น |
| `DUTY_POINT` | จุดเวร |
| `TIME_SLOT` | ช่วงเวลา (เช้า/พักกลางวัน/เย็น) |
| `WEEKDAY` | วันในสัปดาห์ |
| `DUTY_TEAM` | ทีมเวร/สายชั้น 🔎 |
| `ROLE` | บทบาทในระบบ |

ผลลัพธ์ต่อกลุ่ม: จำนวนครู · เวรที่ต้องอยู่ · อยู่ครบ · สาย · อยู่ไม่ครบ · ไม่อยู่ · มอบหมายแทน · **% การปฏิบัติงาน**
กดเข้าไปดูรายชื่อครูในกลุ่มได้ (drill-down) และเลือกได้ว่าจะนับ "ครูตามตาราง" หรือ "ครูที่ปฏิบัติจริง"

## 6. งานใหม่ E — ทำให้ใช้ง่ายและเร็ว: หน้า "วันนี้" แบบเดียวจบ

ปัญหาเดิม: คำตอบ 5 ข้อที่ผู้บริหารอยากรู้กระจายอยู่ 4 หน้า
แก้: **1 action / 1 รอบเรียก** → `todaySummary`

การ์ดต่อ 1 จุดเวร แสดงครบใน 1 สายตา
```
┌──────────────────────────────────────────────┐
│ ประตูหน้าโรงเรียน · 07:00–08:00              │
│ ครูสมชาย ใจดี            🟢 อยู่ครบ 06:52    │
│ 📷 2 ภาพ  📍 12 ม.  📝 ไม่มีเหตุการณ์        │
│ 🔁 เปลี่ยนจาก ครูสมหญิง — อนุมัติโดย         │
│    หัวหน้าเวร (ครูวิชัย) 20 ก.ย. 69 16:30    │
└──────────────────────────────────────────────┘
```

### มาตรการด้านความเร็ว (เพิ่มจากที่ทำแล้ว)
1. `todaySummary` ประกอบข้อมูลฝั่งเซิร์ฟเวอร์ครั้งเดียว — ลดจาก 5–7 รอบเรียกเหลือ 1
2. แคชผลลัพธ์รายวันใน `CacheService` (TTL 60 วิ) ล้างอัตโนมัติเมื่อมีเช็คอิน/ปรับเวร
3. เก็บ `summary_cache` รายวันของวันที่ผ่านมาแล้วลงชีต 🔎 — วันเก่าไม่ต้องคำนวณใหม่เลย
4. เมนูลดจาก 20 หน้าเหลือ **5 หน้าหลัก** (วันนี้ · เวรของฉัน · จัดเวร · รายงาน · ตั้งค่า) ที่เหลือย้ายไปเป็นเมนูย่อย

## 7. สรุปการเปลี่ยนแปลงฐานข้อมูล

### คอลัมน์ที่เพิ่ม 🔎
| ตาราง | คอลัมน์ใหม่ |
|---|---|
| `DUTY_ASSIGNMENTS` | `pin_mode`, `pin_reason`, `pin_by`, `pin_at` |
| `DAILY_SCHEDULE` | `point_rotation_offset`, `source` (`ROTATION`\|`PIN`\|`MANUAL`\|`SWAP`) |
| `SWAP_REQUESTS` | `approver_role`, `approval_level` (1=หัวหน้าเวร 2=หัวหน้างาน 3=ผู้บริหาร) |

### คีย์ตั้งค่าใหม่ใน `CONFIG`
```
point_rotation_mode          = OFF | SEMESTER | WEEKLY | EVERY_N_DAYS | DAILY
point_rotation_n_days        = 5
point_rotation_respect_pin   = true
attendance_group_default     = DEPARTMENT
evidence_require_photo       = true
evidence_min_photos          = 1
late_grace_minutes           = 10
```

ทั้งหมดต้องมีฟังก์ชัน migration ที่ **เติมคอลัมน์ให้ชีตเดิมโดยไม่ทำข้อมูลหาย** (`MIGRATE_v2()` เรียกจากเมนู Apps Script)

### API actions ที่เพิ่ม (~12 รายการ)
```
todaySummary                 pointRotationGet         pointRotationSet
pointRotationPreview         pinList                  pinSet
pinClear                     reportDailyPerformance   reportDailyPerformancePdf
reportAttendanceByGroup      reportAttendanceDrill    migrateV2
```

## 8. เกณฑ์ตรวจรับ (Acceptance Criteria)

1. ตั้ง `point_rotation_mode = WEEKLY` แล้วพรีวิว 4 สัปดาห์ → ครูในกลุ่มหมุนจุดครบวงรอบ ไม่มีที่นั่งว่างและไม่มีครูซ้อนสองจุดในช่วงเวลาเดียวกัน
2. ปักหมุด 1 ที่นั่งเป็น `POINT` → หมุนจุดกี่รอบครูคนนั้นก็ยังอยู่จุดเดิม ที่นั่งอื่นหมุนกันเองปกติ
3. ปักหมุดโดยไม่กรอกเหตุผล → ระบบปฏิเสธ
4. `DAILY_HEAD` เปิดหน้าตั้งค่าการหมุน → เห็นข้อมูล แต่ปุ่มปักหมุดถูกปิด และเรียก `pinSet` ตรง ๆ ได้ 403
5. หมุนจุดย้อนหลังในวันที่มีเช็คอินแล้ว → ระบบบล็อกพร้อมข้อความชัดเจน
6. รายงานรายวัน 1 หน้า แสดงครบ: ครูตามตาราง · ครูจริง · สถานะ · เวลา · GPS · ภาพ · ผู้อนุมัติ
7. เปลี่ยนเวรที่อนุมัติโดยหัวหน้าเวร กับที่อนุมัติโดยผู้บริหาร → รายงานแสดง **ระดับผู้อนุมัติต่างกัน**
8. สรุปอยู่/ไม่อยู่ แยกตามกลุ่มสาระ → ผลรวมทุกกลุ่ม = จำนวนเวรทั้งหมดในช่วงวันที่เลือก (ตรวจยอดได้)
9. เปลี่ยน `groupBy` เป็น `DUTY_POINT` / `TIME_SLOT` / `WEEKDAY` → ยอดรวมต้องเท่ากันทุกแบบ
10. หน้า "วันนี้" โหลดเสร็จใน **1 รอบเรียก** และแสดงผลภายใน 3 วินาทีเมื่อมีแคช
11. `original_teacher_id` ไม่ถูกเขียนทับในทุกเส้นทางใหม่ (ตรวจด้วยชุดทดสอบเดิม)
12. `MIGRATE_v2()` รันซ้ำได้ (idempotent) และข้อมูลเดิมไม่หาย
13. ชุดทดสอบเดิมผ่านทั้งหมด + ทดสอบใหม่อย่างน้อย 30 ข้อสำหรับ `PR_applyToSeats_` และการนับกลุ่ม
