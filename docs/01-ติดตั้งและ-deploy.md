# 01 — ติดตั้งและ Deploy

## สิ่งที่ต้องมี

- บัญชี Google 1 บัญชีสำหรับผู้ติดตั้ง (บัญชีโรงเรียนหรือ Gmail ก็ได้) — **ครูไม่ต้องมีบัญชี Google**
- สิทธิ์สร้าง Google Sheets และโฟลเดอร์ใน Google Drive
- (ถ้าใช้ clasp) Node.js 18 ขึ้นไป

---

## ขั้นที่ 1 — นำโค้ดขึ้นโปรเจกต์ Apps Script

### ทางเลือก A: clasp

```bash
npm i -g @google/clasp
clasp login

# สร้างโปรเจกต์ใหม่ผูกกับสเปรดชีต
clasp create --type sheets --title "CWK DutyFlow" --rootDir src

# หรือใช้โปรเจกต์เดิม
cp .clasp.json.example .clasp.json     # แล้วใส่ scriptId

clasp push
```

### ทางเลือก B: วางด้วยมือ

1. สร้าง Google Sheets ใหม่ ตั้งชื่อ `CWK DutyFlow Database`
2. เมนู **ส่วนขยาย > Apps Script**
3. สร้างไฟล์ให้ครบตามรายชื่อใน `src/`
   - ไฟล์นามสกุล `.gs` → สร้างเป็น **สคริปต์** (ไม่ต้องพิมพ์ `.gs`)
   - ไฟล์นามสกุล `.html` → สร้างเป็น **HTML**
4. เปิด **การตั้งค่าโปรเจกต์** แล้วติ๊ก *แสดงไฟล์ appsscript.json ในตัวแก้ไข* จากนั้นวางเนื้อหา `appsscript.json`

---

## ขั้นที่ 2 — ติดตั้งฐานข้อมูล

ในตัวแก้ไข Apps Script

1. เลือกฟังก์ชัน **`ติดตั้งระบบ`** จากรายการด้านบน
2. กด **เรียกใช้**
3. อนุญาตสิทธิ์ตามที่ระบบร้องขอ (ครั้งแรกจะมีหน้าเตือน "ยังไม่ได้ยืนยัน" ให้กด *ขั้นสูง > ไปที่ ... (ไม่ปลอดภัย)* ซึ่งเป็นเรื่องปกติของสคริปต์ที่เขียนเอง)

ระบบจะ

- สร้างชีตครบ **14 ตาราง** พร้อมหัวตาราง
- เติมคอลัมน์ที่ขาดให้ชีตเดิมโดยไม่ทำข้อมูลหาย
- สร้างโฟลเดอร์ `CWK DutyFlow` ใน Drive พร้อมโฟลเดอร์ย่อย *ภาพหลักฐานการอยู่เวร* และ *รายงาน*
- บันทึก `SPREADSHEET_ID`, `PHOTO_FOLDER_ID`, `REPORT_FOLDER_ID`, `SESSION_SECRET` (กุญแจลงลายมือชื่อเซสชัน) ลง Script Properties
- เติมค่าตั้งค่าเริ่มต้น 40 รายการลงชีต `CONFIG`
- **สร้างบัญชีผู้ดูแลระบบ `admin` พร้อมรหัสผ่านชั่วคราว** (ถ้ายังไม่มีผู้ดูแลที่เข้าสู่ระบบได้)

ชื่อผู้ใช้และรหัสผ่านชั่วคราวจะแสดงในกล่องข้อความเมื่อรันจากเมนูสเปรดชีต
หรือใน **บันทึกการดำเนินการ (Execution log)** ด้านล่างเมื่อรันจากตัวแก้ไข Apps Script

```
บัญชีผู้ดูแลระบบสำหรับเข้าสู่ระบบ (ผู้ดูแล ระบบ)
  ชื่อผู้ใช้: admin
  รหัสผ่านชั่วคราว: k7mxq2pa
```

> จดไว้ก่อนปิด ระบบเก็บเฉพาะค่า hash ดูรหัสผ่านย้อนหลังไม่ได้
> รันซ้ำได้เสมอเมื่ออัปเดตเวอร์ชัน ข้อมูลเดิมไม่หาย และไม่สร้างผู้ดูแลซ้ำ

---

## ขั้นที่ 3 — Deploy เป็นเว็บแอป

**ทำให้ใช้งาน > การทำให้ใช้งานได้ใหม่ > เลือกประเภท > เว็บแอป**

| ตัวเลือก | ค่า | เหตุผล |
|---|---|---|
| คำอธิบาย | `CWK DutyFlow v2` | ระบุเวอร์ชันไว้ย้อนดูได้ |
| ดำเนินการในฐานะ | **ฉัน** | ระบบเข้าถึงสเปรดชีตและ Drive ด้วยสิทธิ์ผู้ติดตั้ง ครูไม่ต้องได้สิทธิ์ไฟล์เอง |
| ผู้ที่มีสิทธิ์เข้าถึง | **ทุกคน** (Anyone) | ครูเปิดลิงก์ได้โดยไม่ต้องลงชื่อเข้า Google แล้วเข้าสู่ระบบด้วยชื่อผู้ใช้/รหัสผ่านของระบบ |

> ค่าเหล่านี้ตั้งไว้แล้วใน `appsscript.json` (`executeAs: USER_DEPLOYING`, `access: ANYONE_ANONYMOUS`)
>
> ถ้าไม่มีตัวเลือก **ทุกคน** ให้เลือก แปลว่าผู้ดูแล Google Workspace ของโรงเรียนปิดการแชร์ภายนอกไว้
> ให้ขอผู้ดูแลโดเมนเปิด หรือติดตั้งด้วยบัญชี Gmail ทั่วไปแทน
>
> ใครมีลิงก์ก็เปิดหน้าเข้าสู่ระบบได้ แต่ดูหรือแก้ข้อมูลได้เฉพาะเมื่อเข้าสู่ระบบสำเร็จ
> ทุกคำสั่งตรวจเซสชันและสิทธิ์ฝั่งเซิร์ฟเวอร์ และฟังก์ชันฝั่งเซิร์ฟเวอร์ที่ถูกเรียกตรงจากเบราว์เซอร์
> จะอ่าน/เขียนข้อมูลไม่ได้ ถ้าไม่ได้ผ่านประตู `api()`

## ขั้นที่ 4 — เปิดใช้งาน

1. คัดลอก URL ที่ได้จากการ Deploy
2. **ตัด `/u/0/`, `/u/1/`, `/u/2/` ออกจาก URL** ถ้ามี

   ```
   ❌ https://script.google.com/macros/u/2/s/AKfy.../exec
   ✅ https://script.google.com/macros/s/AKfy.../exec
   ```

3. เข้าสู่ระบบด้วย `admin` และรหัสผ่านชั่วคราวจากขั้นที่ 2
4. ระบบบังคับให้ตั้งรหัสผ่านใหม่ของตนเองทันที แล้วจึงเข้าหน้าหลัก

---

## ขั้นที่ 5 — สร้างบัญชีให้ครู

หน้า **ข้อมูลหลัก > ครู**

| วิธี | ใช้เมื่อ |
|---|---|
| **+ เพิ่มครู** | ทีละคน — กรอกชื่อผู้ใช้ ถ้าเว้นรหัสผ่าน ระบบสร้างรหัสชั่วคราวให้และแสดง **ครั้งเดียว** |
| **นำเข้าหลายรายการ** | วางจาก Excel/Sheets — ผลลัพธ์มีตารางรหัสผ่านชั่วคราวให้คัดลอกไปพิมพ์แจก |
| **ออกรหัสผ่านชั่วคราว** | ปุ่มนี้ขึ้นเมื่อมีครูที่ยังเข้าสู่ระบบไม่ได้ (เช่น ย้ายมาจากระบบเดิม) |
| **รีเซ็ตรหัสผ่าน** | ครูลืมรหัสผ่านหรือถูกพักบัญชีเพราะใส่ผิดหลายครั้ง |

กฎชื่อผู้ใช้: ยาว 3–32 ตัว ขึ้นต้นด้วยตัวอักษรภาษาอังกฤษ ใช้ได้เฉพาะ `a-z 0-9 . _ -`
(ตัวพิมพ์ใหญ่ถูกแปลงเป็นตัวเล็กให้อัตโนมัติ เช่น `SomChai` → `somchai`)

ค่าที่เกี่ยวข้องอยู่ที่ **ตั้งค่า > การเข้าสู่ระบบ**

| ค่า | เริ่มต้น |
|---|---|
| `session_timeout_min` ออกจากระบบอัตโนมัติเมื่อไม่ได้ใช้งาน | 360 นาที (ตั้งได้ 15–1440) |
| `login_max_attempts` ใส่รหัสผิดได้กี่ครั้งก่อนพักบัญชี | 5 |
| `login_lock_min` พักบัญชีกี่นาที | 15 |
| `password_min_length` ความยาวรหัสผ่านขั้นต่ำ | 6 |
| `password_force_change` บังคับตั้งรหัสใหม่หลังรับรหัสชั่วคราว | เปิด |

> **โดเมนโรงเรียน** (ตั้งค่า > โรงเรียน) ไม่เกี่ยวกับการเข้าสู่ระบบแล้ว
> ใช้เฉพาะกำหนดว่าไฟล์ภาพ/PDF ใน Drive แชร์ให้คนในโดเมนเปิดได้ (เว้นว่าง = ส่วนตัว)

---

## ขั้นที่ 6 — ตั้งทริกเกอร์ (ไม่บังคับ)

**ตัวทริกเกอร์ > เพิ่มทริกเกอร์**

| ฟังก์ชัน | ประเภท | เวลา |
|---|---|---|
| `แจ้งเตือนเวรประจำวัน` | ตามเวลา · รายวัน | 06:00–07:00 |
| `สรุปผู้ไม่อยู่เวรประจำวัน` | ตามเวลา · รายวัน | 17:00–18:00 |
| `สร้างตารางเวรล่วงหน้าอัตโนมัติ` | ตามเวลา · รายสัปดาห์ | คืนวันอาทิตย์ |

ต้องเปิด **ตั้งค่า > การแจ้งเตือน > เปิดการแจ้งเตือนทางอีเมล** ก่อน มิฉะนั้นทริกเกอร์จะไม่ส่งอะไรเลย

---

## การอัปเดตเวอร์ชันภายหลัง

```bash
clasp push
```

จากนั้น

1. รัน **`ติดตั้งระบบ`** อีกครั้ง (เติมคอลัมน์ใหม่ให้ชีตเดิม)
   - ถ้าอัปเดตจากเวอร์ชันที่เข้าด้วยอีเมล: ครูเดิมได้ชื่อผู้ใช้จากส่วนหน้า @ ของอีเมลอัตโนมัติ
     และผู้ดูแลระบบเดิมได้รหัสผ่านชั่วคราว (แสดงในกล่องข้อความ) — เข้าสู่ระบบแล้วไปที่
     **ข้อมูลหลัก > ครู > ออกรหัสผ่านชั่วคราว** เพื่อสร้างรหัสผ่านให้ครูที่เหลือ
   - ต้องเปลี่ยน *ผู้ที่มีสิทธิ์เข้าถึง* เป็น **ทุกคน** ตอน Deploy (หรือ `clasp push` ไฟล์ `appsscript.json` ใหม่)
2. **ทำให้ใช้งาน > จัดการการทำให้ใช้งานได้ > แก้ไข > เวอร์ชันใหม่**
   *URL เดิมยังใช้ได้ ไม่ต้องแจ้งครูใหม่*
3. รัน **`ตรวจสอบระบบ`** เพื่อยืนยันว่าทุกอย่างครบ

> แก้โค้ดแล้วไม่ Deploy ใหม่ = ผู้ใช้ยังเห็นเวอร์ชันเดิม เป็นสาเหตุที่พบบ่อยมาก
