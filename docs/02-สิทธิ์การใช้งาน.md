# 02 — สิทธิ์การใช้งาน 5 ระดับ

ทุกสิทธิ์ตรวจสอบ **ฝั่งเซิร์ฟเวอร์** ในทุกคำสั่ง การซ่อนปุ่มบนหน้าจอเป็นเพียงความสะดวก

## รายละเอียดสำคัญ

### ครู (TEACHER)

เห็นเฉพาะแถวที่ตนเองเป็นครูตามตารางหรือครูที่ปฏิบัติจริง
หน้า "วันนี้" ของครูจะสรุปเฉพาะเวรของตนเอง ไม่เห็นภาพรวมทั้งโรงเรียน
ข้อมูลครูคนอื่นเห็นเพียงชื่อ รหัส และกลุ่มสาระ (ไม่เห็นอีเมล เบอร์โทร บทบาท)

### หัวหน้าเวรประจำวัน (DAILY_HEAD)

จุดขายของบทบาทนี้คือ **จัดเวรเฉพาะรายวันได้**

- เปลี่ยนครูที่จุดใดจุดหนึ่งของวันนั้น (ปุ่ม "เปลี่ยนครูเวร" บนการ์ด)
- สลับครูระหว่างสองจุดภายในวันเดียวกัน (ปุ่ม "สลับจุด")
- ระบบจะเสนอเฉพาะครูที่ **ว่างจริง** ในช่วงเวลานั้น และบอกว่าใครติดเวรอยู่ที่ไหน
- **บังคับกรอกเหตุผล** ทุกครั้ง
- ทุกการปรับถูกบันทึกเป็นคำขอที่อนุมัติแล้ว โดยมีชื่อและ **ระดับ 1 (หัวหน้าเวรประจำวัน)** เป็นผู้อนุมัติ จึงปรากฏในรายงานการเปลี่ยนเวร
- ปรับย้อนหลังได้ตามค่า `daily_adjust_backdays` (เริ่มต้น 1 วัน)
- **แก้แม่แบบของภาคเรียนไม่ได้** และ **ปักหมุดไม่ได้**

### หัวหน้างานเวร (DUTY_ADMIN)

ผู้ดูแลงานเวรตัวจริง — จัดแม่แบบภาคเรียน ตั้งกฎการหมุน ปักหมุด และสร้างตารางรายวัน
อนุมัติในระดับ 2

### ผู้บริหาร (EXECUTIVE)

เน้นการมองภาพรวมและอนุมัติระดับสูงสุด ไม่แก้ข้อมูลหลัก
เห็นแดชบอร์ด แนวโน้มรายวัน และกลุ่มสาระที่ควรติดตาม

### ผู้ดูแลระบบ (SYS_ADMIN)

ทำได้ทุกอย่าง รวมถึงตรวจสอบและซ่อมข้อมูล
ระบบ **ไม่ยอมให้ลดสิทธิ์หรือระงับผู้ดูแลระบบคนสุดท้าย**

## ระดับผู้อนุมัติการเปลี่ยนเวร

| ระดับ | บทบาท |
|:--:|---|
| 1 | หัวหน้าเวรประจำวัน |
| 2 | หัวหน้างานเวร |
| 3 | ผู้บริหาร / ผู้ดูแลระบบ |

- ค่า `swap_min_level` กำหนดระดับขั้นต่ำที่อนุมัติได้ (เริ่มต้น 1)
- รายงานแสดงระดับผู้อนุมัติของทุกการเปลี่ยนเวร และ **ขึ้นป้ายแดง** เมื่อพบการเปลี่ยนครูที่ไม่มีบันทึกการอนุมัติ
- **ห้ามอนุมัติคำขอที่ตนเองเป็นผู้ขอหรือผู้รับ** — ระบบปฏิเสธเสมอ

## เงื่อนไขการเข้าระบบ

ผู้ใช้จะเข้าได้ต่อเมื่อครบทุกข้อ

1. เข้าสู่ระบบด้วยบัญชี Google และระบบอ่านอีเมลได้
2. อีเมลอยู่ในโดเมนโรงเรียน (ถ้ากำหนดไว้) หรือเป็นอีเมลผู้ติดตั้ง
3. มีอีเมลนั้นในชีต `TEACHERS`
4. สถานะเป็น `ACTIVE`

ถ้าไม่ผ่านข้อใด หน้าจอจะบอกสาเหตุและวิธีแก้เป็นภาษาไทย ไม่ใช่หน้าขาวหรือกล่องว่าง
