# CWK DutyFlow v2

**ระบบบริหารเวรประจำวัน โรงเรียนจุนวิทยาคม อำเภอจุน จังหวัดพะเยา**

Google Apps Script (V8) + HTML Service + Google Sheets เป็นฐานข้อมูล + Google Drive เก็บภาพหลักฐาน
ไม่ใช้ฐานข้อมูลภายนอกใด ๆ

**เข้าสู่ระบบด้วยชื่อผู้ใช้และรหัสผ่าน** — ครูไม่ต้องมีหรือลงชื่อเข้าบัญชี Google ของโรงเรียน
เปิดลิงก์แล้วพิมพ์ชื่อผู้ใช้/รหัสผ่านที่ผู้ดูแลแจกให้ได้เลย สิทธิ์ 5 ระดับยังเหมือนเดิมทุกประการ

## ระบบนี้ตอบคำถามอะไร

| คำถาม | ตอบที่ไหน |
|---|---|
| ครูคนไหนอยู่เวร วันไหน จุดไหน | หน้า **วันนี้** — การ์ดรายจุด เลือกวันย้อนหลัง/ล่วงหน้าได้ |
| อยู่เวรจริงหรือไม่ | ป้ายสถานะ 4 แบบ: อยู่ครบ · สาย · อยู่ไม่ครบ · ไม่อยู่ |
| มีหลักฐานไหม หลักฐานคืออะไร | เวลาเข้า–ออก · ระยะห่าง GPS · ภาพถ่าย · เหตุการณ์ที่บันทึก พร้อมป้าย 🟢🟡🔴 |
| เปลี่ยนเวรแล้วใครอนุมัติ | แสดงชื่อผู้อนุมัติ **พร้อมระดับ** (หัวหน้าเวร / หัวหน้างาน / ผู้บริหาร) |
| หมุนเวรข้ามวันต่อภาคเรียน | จันทร์→อังคาร→พุธ→พฤหัสบดี→ศุกร์→จันทร์ พร้อมพรีวิวและย้อนกลับได้ |
| หมุนจุดภายในแต่ละวัน | 5 โหมด: ปิด · ต้นภาคเรียน · รายสัปดาห์ · ทุก N วันทำการ · รายวัน |
| กำหนดจุดเฉพาะบุคคล | ปักหมุด 4 ระดับ: ตรึงจุด · ตรึงวัน · ตรึงทั้งคู่ · ไม่ตรึง (บังคับกรอกเหตุผล) |

| สรุปครูอยู่/ไม่อยู่ แยกกลุ่ม | 6 มิติ: กลุ่มสาระ · จุดเวร · ช่วงเวลา · วันในสัปดาห์ · บทบาท (เจาะดูรายชื่อได้) |

## ติดตั้ง

### วิธีที่ 1 — ใช้ clasp (แนะนำ)

```bash
npm i -g @google/clasp
clasp login
clasp create --type sheets --title "CWK DutyFlow" --rootDir src
# หรือใช้โปรเจกต์เดิม: คัดลอก .clasp.json.example เป็น .clasp.json แล้วใส่ scriptId
clasp push
```

### วิธีที่ 2 — วางโค้ดด้วยมือ

1. สร้าง Google Sheets ใหม่ → เมนู **ส่วนขยาย > Apps Script**
2. สร้างไฟล์ตามรายชื่อใน `src/` แล้ววางเนื้อหาให้ตรงกัน
   (ไฟล์ `.gs` เป็นไฟล์สคริปต์ · ไฟล์ `.html` เป็นไฟล์ HTML)
3. เปิด `appsscript.json` ผ่าน **การตั้งค่าโปรเจกต์ > แสดงไฟล์ appsscript.json**

### ติดตั้งฐานข้อมูล

ในตัวแก้ไข Apps Script เลือกฟังก์ชัน **`ติดตั้งระบบ`** แล้วกดเรียกใช้ 1 ครั้ง
ระบบจะสร้างชีตครบ 14 ตาราง เติมคอลัมน์ที่ขาด สร้างโฟลเดอร์ Drive
และ **สร้างบัญชีผู้ดูแลระบบ `admin` พร้อมรหัสผ่านชั่วคราว** แสดงในกล่องข้อความ
(ถ้ารันจากตัวแก้ไข Apps Script ให้ดูที่ **บันทึกการดำเนินการ**) — จดไว้ใช้เข้าสู่ระบบครั้งแรก
**รันซ้ำได้เสมอ ข้อมูลเดิมไม่หาย** และจะไม่สร้างผู้ดูแลซ้ำถ้ามีผู้ดูแลที่เข้าสู่ระบบได้แล้ว

### Deploy เป็นเว็บแอป

**ทำให้ใช้งาน > การทำให้ใช้งานได้ใหม่ > เว็บแอป**

| ตัวเลือก | ค่าที่ควรใช้ |
|---|---|
| ดำเนินการในฐานะ | **ฉัน** (ผู้ติดตั้ง) |
| ผู้ที่มีสิทธิ์เข้าถึง | **ทุกคน** (Anyone) — ครูไม่ต้องลงชื่อเข้า Google ระบบตรวจชื่อผู้ใช้/รหัสผ่านเอง |

เปิด URL ที่ได้ **โดยตัด `/u/2/` หรือ `/u/1/` ออกจากลิงก์** (เป็นสาเหตุอันดับหนึ่งของหน้า Google Drive Error)

### เข้าสู่ระบบครั้งแรกและแจกบัญชีให้ครู

1. เปิดลิงก์เว็บแอป เข้าด้วย `admin` และรหัสผ่านชั่วคราวจากขั้นติดตั้ง แล้วตั้งรหัสผ่านใหม่ของตนเอง
2. **ข้อมูลหลัก > ครู > + เพิ่มครู** — กรอกชื่อผู้ใช้ (a-z ตัวเล็ก ตัวเลข `.` `_` `-`)
   ถ้าเว้นรหัสผ่านไว้ ระบบจะสร้างรหัสผ่านชั่วคราวและแสดงให้ **ครั้งเดียว** หลังบันทึก
3. หรือ **นำเข้าหลายรายการ** จาก Excel/Sheets — คอลัมน์ `ชื่อผู้ใช้`, `รหัสผ่าน` ไม่บังคับ
   (ชื่อผู้ใช้ว่าง = ใช้ส่วนหน้า @ ของอีเมลหรือรหัสครู · รหัสผ่านว่าง = ระบบสร้างให้)
4. ครูเข้าครั้งแรกด้วยรหัสผ่านชั่วคราว แล้วระบบบังคับให้ตั้งรหัสผ่านใหม่ของตนเอง
5. ครูลืมรหัสผ่าน → ผู้ดูแลกด **รีเซ็ตรหัสผ่าน** ที่แถวของครูคนนั้น
6. ผู้ดูแลระบบลืมรหัสผ่านเอง → เจ้าของสคริปต์รัน **`รีเซ็ตรหัสผ่านผู้ดูแลระบบ`** ในตัวแก้ไข Apps Script

> **ย้ายจากเวอร์ชันเดิมที่เข้าด้วยอีเมล:** รัน `ติดตั้งระบบ` อีกครั้ง ระบบจะตั้งชื่อผู้ใช้ให้ครูเดิมทุกคน
> จากส่วนหน้า @ ของอีเมล และออกรหัสผ่านชั่วคราวให้ผู้ดูแลระบบเดิม จากนั้นกด
> **ข้อมูลหลัก > ครู > ออกรหัสผ่านชั่วคราว** เพื่อสร้างรหัสผ่านให้ครูที่เหลือพร้อมกันทีเดียว

## เริ่มใช้งานครั้งแรก (6 ขั้นตอน)

หน้า **วันนี้** และ **ตั้งค่า** จะแสดงรายการนี้พร้อมปุ่มลัด และทำเครื่องหมายให้อัตโนมัติเมื่อทำครบ

1. **เพิ่มข้อมูลครู** — ทีละคน หรือวางจาก Excel/Sheets แล้วกดนำเข้า (ตรวจสอบก่อนบันทึกจริง)
2. **กำหนดช่วงเวลาเวร** — เช่น เวรเช้า 07:00–08:20
3. **กำหนดจุดเวร** — ชื่อ พิกัด รัศมี จำนวนที่นั่ง และกลุ่มการหมุน (มีปุ่ม "ใช้พิกัดปัจจุบันของฉัน")
4. **สร้างและเปิดใช้ภาคเรียน** — ปี พ.ศ. ภาคเรียน วันเปิด–ปิด
5. **จัดเวรประจำภาคเรียน** — วัน × ช่วงเวลา × จุด × ที่นั่ง × ครู
6. **สร้างตารางเวรรายวัน** — ระบบแปลงแม่แบบเป็นตารางจริง พร้อมหมุนจุดตามที่ตั้งค่า

ต้องการทดลองเร็ว ๆ กดปุ่ม **"ใส่ข้อมูลตัวอย่าง"** เพื่อสร้างช่วงเวลา 3 ช่วง จุดเวร 5 จุด และภาคเรียนปัจจุบันให้อัตโนมัติ

## การหมุนเวร

### หมุนวัน (ต่อภาคเรียน)

```
newWeekday = ((oldWeekday - 1 + dayShift) mod 5) + 1
ศุกร์ + 1 → จันทร์
```

**จัดเวร > การหมุนเวร > พรีวิวการหมุนวัน** เลือกภาคเรียนต้นทาง ดูผลก่อน แล้วจึงคัดลอกไปภาคเรียนใหม่
ย้อนกลับได้ตราบใดที่ยังไม่ได้สร้างตารางรายวันของภาคเรียนนั้น

### หมุนจุด (ภายในวัน)

```
newSeatIndex = (oldSeatIndex + offset) mod groupSize
```

| โหมด | offset |
|---|---|
| `OFF` | ไม่หมุน |
| `SEMESTER` | หมุนครั้งเดียวตอนคัดลอกภาคเรียน |
| `WEEKLY` | สัปดาห์ที่ของภาคเรียน (ค่าเริ่มต้น) |
| `EVERY_N_DAYS` | `floor(ลำดับวันทำการ / N)` |
| `DAILY` | ลำดับวันทำการ |

- หมุนเฉพาะที่นั่งใน **ช่วงเวลาเดียวกัน + กลุ่มหมุนเดียวกัน** เรียงตาม `rotation_order`
- **ลำดับวันทำการนับแบบข้ามวันหยุด** รอบการหมุนจึงไม่เคลื่อนเมื่อมีวันหยุด
- คำนวณตอนสร้างตารางรายวัน ไม่เก็บตารางซ้ำซ้อน
- **พรีวิวล่วงหน้า 4 สัปดาห์ได้ก่อนบันทึก**

### ปักหมุดจุดเฉพาะบุคคล

| โหมด | ผล |
|---|---|
| `POINT` | ตรึงจุด แต่ยังหมุนวันได้ |
| `DAY` | ตรึงวัน แต่ยังหมุนจุดได้ |
| `ALL` | ตรึงทั้งวันและจุด |
| `NONE` | หมุนได้อิสระ |

บังคับกรอกเหตุผลอย่างน้อย 5 ตัวอักษร · ตั้งค่าได้เฉพาะหัวหน้างานเวรและผู้ดูแลระบบ
**หัวหน้าเวรประจำวันดูได้แต่แก้ไม่ได้** (ตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์ ไม่ใช่แค่ซ่อนปุ่ม)

## การเข้าสู่ระบบ

| เรื่อง | การทำงาน |
|---|---|
| เก็บรหัสผ่าน | PBKDF2-HMAC-SHA256 + salt สุ่มต่อคน — ในชีตมีแต่ค่า hash ไม่มีรหัสผ่านจริง |
| เซสชัน | token ลงลายมือชื่อด้วย HMAC-SHA256 (กุญแจลับ `SESSION_SECRET` ใน Script Properties) ตรวจได้ทุกคำขอโดยไม่พึ่งแคช · หน้าเว็บจำไว้ในหน่วยความจำเท่านั้น (รีเฟรชหน้า = เข้าสู่ระบบใหม่) |
| หมดเวลา | ไม่ได้ใช้งานเกิน `session_timeout_min` (เริ่มต้น 360 นาที ตั้งได้ 15–1440) ต้องเข้าสู่ระบบใหม่ · ใช้งานต่อเนื่องระบบต่ออายุให้เอง |
| ให้ทุกคนออกจากระบบ | ลบ `SESSION_SECRET` ใน Script Properties ระบบจะสร้างกุญแจใหม่เมื่อมีคนเข้าสู่ระบบครั้งถัดไป |
| ใส่รหัสผิด | ครบ `login_max_attempts` ครั้ง (5) พักบัญชี `login_lock_min` นาที (15) · ผู้ดูแลรีเซ็ตรหัสผ่านเพื่อปลดได้ทันที |
| รหัสผ่าน | ยาวอย่างน้อย `password_min_length` (6) · ห้ามเหมือนชื่อผู้ใช้ · บังคับตั้งใหม่หลังรับรหัสชั่วคราว (`password_force_change`) |
| เปลี่ยน/รีเซ็ตรหัสผ่าน | เซสชันเดิมบนเครื่องอื่นของบัญชีนั้นหมดอายุทันที |
| ระงับบัญชี | ผู้ใช้หลุดจากระบบทันทีในคำขอถัดไป |
| อีเมล | ไม่ใช้เข้าสู่ระบบแล้ว (ไม่บังคับกรอก) ใช้รับการแจ้งเตือนทางอีเมลเท่านั้น |

ทุกบัญชีเปลี่ยนรหัสผ่านเองได้ที่ปุ่ม **👤 มุมขวาบน > เปลี่ยนรหัสผ่าน** และออกจากระบบได้จากเมนูเดียวกัน

## สิทธิ์การใช้งาน 5 ระดับ

| บทบาท | เห็นอะไร | ทำอะไรได้ |
|---|---|---|
| **ครู** (TEACHER) | เฉพาะเวรของตนเอง | เช็คอิน/เอาต์ · แนบภาพ · แจ้งเหตุการณ์ · ขอเปลี่ยนเวร |
| **หัวหน้าเวรประจำวัน** (DAILY_HEAD) | เวรทุกจุดทุกคน | + **ปรับครูเวรรายวัน** · สลับจุดรายวัน · อนุมัติคำขอ (ระดับ 1) · ดูรายงาน |
| **หัวหน้างานเวร** (DUTY_ADMIN) | ทุกอย่าง | + จัดเวรภาคเรียน · ปักหมุด · ตั้งค่าการหมุน · สร้างตาราง · ข้อมูลหลัก · อนุมัติ (ระดับ 2) |
| **ผู้บริหาร** (EXECUTIVE) | ทุกอย่าง | ดูรายงานทั้งหมด · อนุมัติ (ระดับ 3) |
| **ผู้ดูแลระบบ** (SYS_ADMIN) | ทุกอย่าง | + ตั้งค่าระบบ · ตรวจสอบ/ซ่อมข้อมูล · ประวัติการใช้งาน |

หัวหน้าเวรปรับเวรย้อนหลังได้ตามค่า `daily_adjust_backdays` (ค่าเริ่มต้น 1 วัน) · ผู้ดูแลไม่จำกัด
**ห้ามอนุมัติคำขอที่ตนเองเกี่ยวข้อง** — ระบบปฏิเสธเสมอ

## กฎเหล็กที่ระบบบังคับใช้

1. Primary Key เป็น UUID เสมอ — ไม่ใช้เลขแถว
2. **ห้ามเขียนทับ `original_teacher_id`** เมื่อเปลี่ยนเวร เปลี่ยนเฉพาะ `effective_teacher_id` (มีชุดทดสอบตรวจทุกไฟล์)
3. ห้ามลบข้อมูลครูถาวร — เปลี่ยนสถานะเป็น INACTIVE
4. ห้ามลบประวัติการอนุมัติและการเช็คอิน
5. ตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์ทุกครั้ง — ไม่เชื่อบทบาทที่ส่งมาจากหน้าเว็บ
   ฟังก์ชันที่หน้าเว็บเรียกตรงได้ (ชื่อไม่ลงท้ายด้วย `_`) เข้าถึงข้อมูลไม่ได้ ถ้าไม่ได้เริ่มจาก `api()`
   คำสั่งของเจ้าของสคริปต์ หรือทริกเกอร์ และ ctx ที่ส่งมาจากหน้าเว็บถูกปฏิเสธเสมอ
6. ภาพหลักฐานไม่ตั้งเป็น "ทุกคนที่มีลิงก์" — ใช้ระดับโดเมนหรือส่วนตัวเท่านั้น
7. Spreadsheet ID / Folder ID อยู่ใน Script Properties เท่านั้น ไม่ส่งไปฝั่งหน้าเว็บ
8. ปรับ/สลับเวรที่มีการเช็คอินไปแล้วไม่ได้
9. ทุกการแก้ไขเก็บค่าก่อนแก้และหลังแก้ใน AUDIT_LOG (ยกเว้น hash รหัสผ่าน ซึ่งไม่ถูกบันทึกเด็ดขาด)
10. ไม่เก็บรหัสผ่านจริงที่ใด — รหัสผ่านชั่วคราวแสดงให้ผู้ดูแลเห็นเพียงครั้งเดียว

## แก้ปัญหาที่พบบ่อย

### กล่องข้อความแจ้งเตือนว่างเปล่า
แก้แล้วในเวอร์ชันนี้ — ทั้ง `api()`, `call()`, `modal()`, `showError()` และ `bootError()`
แทนข้อความว่างด้วยข้อความมาตรฐานเสมอ และมีปุ่ม "ตรวจสอบระบบ" ให้กดต่อได้ทันที

### ทุกช่องขึ้นว่า "(ว่าง)" หรือ "- - - -"
ตารางรายวันอ้างถึงครู/จุด/ช่วงเวลาที่ถูกลบหรือไม่มีอยู่
→ **ตั้งค่า > ตรวจสอบระบบ** จะรายงานจำนวนรายการที่เชื่อมไม่ติด
→ กด **ซ่อมข้อมูล** (ลบเฉพาะรายการที่ยังไม่มีการเช็คอิน) แล้วสั่งสร้างตารางรายวันใหม่

### ภาคเรียนแสดงเป็น "1/0" หรือปีไม่ถูกต้อง
ปีการศึกษาต้องเป็น **พ.ศ.** (เช่น 2569) และภาคเรียนต้องเป็น 1 หรือ 2
→ **ข้อมูลหลัก > ภาคเรียน > แก้ไข** — หน้านี้จะขึ้นป้ายแดงให้เห็นทันทีเมื่อค่าไม่ถูกต้อง

### หน้าค้างที่หน้าจอเริ่มระบบ
มีการตรวจ `document.readyState` และ fallback timeout 3 วินาที
หากยังค้าง แปลว่าเรียกเซิร์ฟเวอร์ไม่สำเร็จ — จะมีข้อความและปุ่ม "ลองใหม่/ตรวจสอบระบบ" แสดงแทน

### เปิดลิงก์แล้วขึ้นหน้า Google Drive Error
- ตัด `/u/2/` หรือ `/u/1/` ออกจาก URL
- ตรวจว่า "ผู้ที่มีสิทธิ์เข้าถึง" ตรงกับบัญชีที่ใช้เปิด
- หลังแก้โค้ดต้อง **Deploy ใหม่** ทุกครั้ง (หรือใช้ Test deployment)

### เข้าสู่ระบบไม่ได้
- **ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง** — ให้ผู้ดูแลกด *รีเซ็ตรหัสผ่าน* แล้วแจ้งรหัสชั่วคราวใหม่
- **บัญชีถูกพักไว้ชั่วคราว** — ใส่ผิดเกินกำหนด รอ 15 นาที หรือให้ผู้ดูแลรีเซ็ตรหัสผ่าน
- **บัญชีถูกระงับ** — ผู้ดูแลกด *เปิดใช้* ที่ ข้อมูลหลัก > ครู
- **ครูเดิมยังไม่มีรหัสผ่าน** — ข้อมูลหลัก > ครู > *ออกรหัสผ่านชั่วคราว*
- **ผู้ดูแลระบบลืมรหัสผ่าน** — รัน `รีเซ็ตรหัสผ่านผู้ดูแลระบบ` ในตัวแก้ไข Apps Script

### ระบบช้า
- เปิดหน้าวันนี้ใช้การเรียกเซิร์ฟเวอร์เพียง **1 รอบ** และแคชผลไว้ 60 วินาที
- ตาราง 13 จาก 14 ตารางแคชไว้ 30 นาที ล้างอัตโนมัติเมื่อมีการแก้ไข
- ถ้าข้อมูลไม่อัปเดต กดปุ่ม ↻ มุมขวาบน หรือ **ตั้งค่า > ล้างแคช**

```bash
npm test
```
